# Codex 插件使用说明

Codex 作为独立的 `pi-web.codex` 插件运行，入口位于 Workspace 工具栏的 Terminal 之后。命令面板也可搜索 **Go to Codex**。插件通过宿主工作区接口通信，沿用机器路由、鉴权和布局；Codex 会话与 Pi 聊天独立。

## 安装和启动

1. 在工作区所在机器安装 Codex CLI，并运行 `codex login` 完成登录。确保启动 `pi-web-sessiond` 的环境可以找到 `codex`，可先执行 `codex --version`。
2. 在本补丁仓库执行 `sh scripts/sync.sh`，然后执行 `sh scripts/install.sh`。
3. 手动重启 sessiond 和 Web 服务。例如使用本仓库管理脚本的实例执行：

   ```bash
   bash scripts/pi-web-run-jmfederico.sh stop
   bash scripts/pi-web-run-jmfederico.sh start
   ```

   实例由 `data/pi-web.conf` 选择，端口和环境变量应与原实例一致。重启会中断正在运行的任务，应先等待任务结束。
4. 选择工作区，打开 **Codex** 后进入会话首页。点击列表中的会话查看历史；也可直接在底部输入并发送，自动新建会话。会话内点击左上角标题前的 **←** 返回首页。

本次验证版本为 **codex-cli 0.162.1**，使用 `codex app-server --listen stdio://`。未对更早版本承诺兼容；初始化或协议操作失败时，请先核对版本和 sessiond 的 PATH。协议依据为 [Codex App Server 官方文档](https://developers.openai.com/codex/app-server)，具体字段同时以该 CLI 生成的 TypeScript schema 验证。

Codex CLI 是可选依赖，插件首次使用时才启动子进程。未安装或未登录时页面显示错误或登录提示，Pi 和 Terminal 仍可使用。插件不会安装 CLI、代为登录或复制认证文件。

## app-server 代理

插件直接启动 `codex app-server`，不会读取 shell alias。app-server 继承 `pi-web-sessiond` 的环境变量，可在 `data/pi-web.conf` 中配置（无需 `export`）：

```bash
HTTP_PROXY='http://10.30.0.16:7890'
HTTPS_PROXY='http://10.30.0.16:7890'
NO_PROXY='localhost,127.0.0.1,::1'
```

也可以在服务尚未启动时，通过启动命令传入：

```bash
HTTP_PROXY=http://10.30.0.16:7890 HTTPS_PROXY=http://10.30.0.16:7890 \
NO_PROXY=localhost,127.0.0.1,::1 bash scripts/pi-web-run-jmfederico.sh start
```

配置文件中的同名变量优先；未填写的变量保留启动环境中的值。这些变量也会被其他服务子进程继承，并非仅作用于 Codex。已有 `NO_PROXY` 例外请保留，并按需补充内部服务地址。

已运行的 sessiond 不会读取新的环境变量，刷新页面或重连 Codex 不会使代理配置生效。需先检查活跃会话、等待任务结束并保存恢复信息，在允许中断时用 `scripts/pi-web-run-jmfederico.sh stop` 停止，再用 `start` 启动。若操作会中断当前维护会话，应由独立维护进程完成停止、启动和就绪检查。

## 页面布局

首页采用紧凑的 **Chats** 列表：每行显示圆点、会话标题及更新时间，默认显示前 5 个。**More** 固定在第 5 个之后，点击展开下方其余会话，再点击收起；展开后可用 **Load older conversations** 加载后续分页。输入区固定在底部，只有发送时才创建新会话。

点击列表进入会话历史，顶部显示会话标题及 pi-web 传入的 `workspace.path`。返回首页后列表重新收起为前 5 个，首页草稿与各会话草稿分别保留。工作目录由宿主工作区决定。

点击输入区的权限标签打开弹出菜单，按 **Ask for approval → Approve for me → Full access** 排列，每项包含图标和说明，当前选项右侧显示对勾。**Full access** 的菜单项和入口均使用黄色盾牌感叹号警告样式。支持方向键导航、Esc 或点击外部关闭。默认 **Full access**，选择按机器／工作区保存在浏览器中，从下一条消息生效。生成中和请求提交中禁止切换。

- **Full access**：`never` + `danger-full-access`，不请求执行审批。
- **Ask for approval**：`on-request` + `workspace-write`，审批交给用户（`user`）。
- **Approve for me**：`on-request` + `workspace-write`，由 Codex 自动审查（`auto_review`），不是无条件批准。

所选模式用于新建、恢复会话，以及每次发送的权限参数，因此已有会话也可在下一轮切换。

底部圆角输入框内，左下角为添加菜单和权限选择器，模型／思考强度选择按钮靠右、位于发送／停止共用按钮左侧，右下角为空闲时的发送按钮；执行中输入为空时显示停止方块，有文字或文件引用时显示 **Queue message**，旁边保留独立的 Stop。提交请求时按钮转圈并禁用，输入框仍可编辑；确认后仅清空已提交的内容，新输入的草稿保留。提交失败保留草稿和文件引用。首页的默认模型和思考强度来自 Codex 按工作目录解析的配置；仅当配置未指定时，才使用后端模型列表标记的默认项。进入会话后显示 Codex 返回的会话设置，发送后再次读取后端设置。模型入口为圆角按钮，初始化、刷新及重新连接后直接显示后端返回的模型名称与思考强度（例如 **GPT-6 Astra Medium**），点击后向上弹出卡片：顶部蓝色标题显示当前思考强度，点击中间的思考强度标题或下方模型名均可打开 **Select model** 自定义列表（当前模型右侧显示勾，支持悬停高亮、上下键及 Home / End 导航）。列表顶部 **Default** 使用后端提供的工作区默认模型和强度；选择模型后返回强度卡片，输入栏显示所选模型与强度，右上角重置按钮清除手动选择（首页恢复工作区默认配置，会话内恢复当前会话设置）。卡片最大宽度为 300px，强度标题为 16px，滑杆滑块为 32px。底部分档滑杆按模型实际支持的强度排序，可拖动、点击或使用键盘方向键切换；切换模型时清除旧强度选择。提交中和生成中禁用设置，缺少推理档位时显示提示，只有一个档位时滑杆不可调整。选择后卡片保持打开，点击外部、移走焦点或按 Esc 关闭。

右侧 **Review** 展示当前消息页中的文件变更和轮次 diff，默认关闭，可通过顶部按钮打开或关闭。打开后，宽面板并排显示，宽度不超过 850px 时以浮层展示。变更数量是变更条目数，不是去重后的文件数。

点击回复中的工作区文件链接，会自动打开 **Review** 并显示该文件的当前内容。支持工作区内的绝对路径、相对路径和 `file:///` 链接，以及 `:行号`、`:行号:列号`、`#L行号` 定位；指定行会滚动到可见区域并高亮。文件按源码显示，**← Changes** 返回变更列表，输入草稿保持不变。长文件可用 Previous lines / Next lines 分段浏览；读取失败可 Retry，二进制文件和内容截断会显示提示。外部网页继续在新标签页打开，工作区外的文件不提供打开入口。切换工作区或会话、关闭 Review 时取消未完成的读取。

## 添加工作区上下文

输入框左下角的 **+** 在输入区上方展开 **Add** 菜单，提供 **Files and folders**、**Upload files** 和 **Plan mode**。选择 Files and folders 打开当前 pi-web 工作区的文件浏览器；通过 **Back to Add** 返回添加菜单。菜单支持方向键、Home / End 导航、Enter 操作、Esc 或点击外部关闭，并适配窄屏。点击目录名进入目录，↑ 返回上级；点击文件名或 **Add** 添加文件，**Add directory** 添加当前目录，也可通过目录行的 Add 选择子目录。支持筛选当前目录；选定后点击 Done、外部区域或 Esc 收起。

已选项在输入框上方显示，可逐项移除。最多选择 20 项，按机器／工作区／会话保存；发送失败时保留，发送成功后清空。Files and folders 仅发送工作区相对路径，Codex 根据任务按需读取。链接条目暂不支持在选择器内添加；服务端拒绝不存在或越出工作区的路径。

## 从本机上传文件和图片

点击 **+ → Upload files**，从浏览器所在电脑或手机选择文件，支持文档、代码、压缩包和图片等文件，可混合多选；也可以在输入框粘贴剪贴板中的文件或截图，或将文件拖入输入区。每条消息最多 10 个本机附件，每个不超过 20 MiB。输入区显示文件名、大小和上传进度，可逐项移除；PNG、JPEG、WebP 和 GIF 还会显示图片缩略图。

上传完成后可与文字一起发送，也可直接发送附件。执行中可将附件消息加入队列，并通过 Steer 补充到当前任务。上传失败会显示错误，移除后重新选择即可重试；发送失败会保留已上传文件。附件按机器／工作区／会话隔离，已上传的草稿附件在刷新后仍可恢复，旧版图片草稿同样兼容。上传中的文件需等待完成后再发送。

文件通过宿主的上传接口保存到当前工作区的上传目录（默认 `.pi-web/uploads/codex/<随机标识>/`）。普通文件的工作区路径随消息发送，Codex 根据任务读取原文件；具体文档格式的解析取决于工作区可用工具。支持的图片以 Codex `localImage` 输入发送，会话中的工作区图片可预览并点击打开。移除附件或发送成功仅清空输入区选择，已上传的文件会保留，供会话恢复时读取。旧宿主缺少上传能力时，Upload files 按钮不可用，需先更新宿主。

## 语音输入

模型选择与发送按钮之间的麦克风按钮始终可见。在 `data/pi-web.conf` 中设置 `PI_WEB_VOICE_INPUT_ENABLED=false` 或未配置时，按钮禁用并提示语音输入已禁用。字段仅接受 `true` / `false`，修改后需在允许中断会话时重新启动服务并刷新页面。设为 `true` 时，当前按钮仍处于禁用状态，提示语音输入尚未实现。语音识别逻辑和独立后台服务代码已移除，不会申请麦克风权限；普通文本编辑和发送按钮照常可用。

后续方案见 [离线语音输入实施计划](语音识别.md)，原服务的部署设计和协议见 [服务设计存档](voice-service.md)。

## Plan 模式

在 Add 菜单开启 **Plan mode** 后，输入区底部的权限选择器右侧显示灯泡图标和 **Plan**，占位文字变为 **Describe your task to generate a plan...**。点击底部 Plan 可关闭，菜单开关同步更新；关闭后隐藏标识并恢复普通占位文字。开关不会自动发送消息，从下一条消息生效，提交中和生成中禁止切换。

Plan 状态按工作区和会话保存在浏览器，刷新后恢复，切换会话互不影响。新会话默认关闭；在首页开启后发送，创建的会话继承该模式。每次发送明确携带 `plan` 或 `default`，后端映射为 Codex 原生 `collaborationMode`，使用原生模式指令，同时保留所选模型、思考强度和权限。发送失败保留草稿、文件引用和待发送模式。

**Asking question** 仅在后端实际请求用户输入时显示，不是 Plan 的固定状态。本次添加菜单不包含 Goal、Sketch 或 Plugins。

## 对话和审批

- 手机触屏或浏览器窗口宽度不超过 760px 时，键盘 Enter 换行，点击发送按钮提交；任务执行中点击 **Queue message** 将补充输入加入队列。桌面端 Enter 发送／入队，Shift+Enter 换行；输入法组合输入期间 Enter 不发送。仅缩窄 Codex 面板不会改变桌面键盘行为。
- 输入框按 ↑ / ↓ 浏览成功发送的输入历史；多行文本仅在首行按 ↑、末行按 ↓ 时切换，往下翻到末尾恢复未发送草稿。历史按机器／工作区／会话隔离，优先读取 Codex 会话最近 100 条用户输入（包括 CLI 中发送的内容），首次打开历史会话也可使用；浏览器记录仅作为离线回退；组合输入、选中文本或按住修饰键时保留原有方向键行为。
- 模型和推理档位来自 app-server；重置按钮恢复后端提供的当前配置。
- 排队消息显示在输入框上方。默认等待当前任务完成，再按加入顺序逐条执行；点击某条消息的 **Steer**，才通过 Codex 原生 `turn/steer` 将该条立即提交给当前轮次。成功后从队列移除；失败时保留，并显示错误。Steer 沿用当前轮次的模型、权限和 Plan 设置。
- 每条排队消息可用 **×** 移除。队列由服务端维护，切换会话、关闭面板或刷新页面后仍可查看，自动续跑不依赖浏览器保持打开。每个会话最多排队 20 条。
- **Stop** 中断当前轮次并暂停队列；下一条任务还在启动时点击 Stop，会在收到该轮次 ID 后中断该任务。任务失败或中断时也暂停。剩余输入保留，点击 **Run next** 恢复顺序执行。自动启动失败时保留该条，不自动反复重试。
- 聊天时间线参考 codex-webui：用户消息、过程说明和最终回答分别呈现；相邻工具活动按轮次分组，执行时展开、完成后收起。
- 命令卡片显示命令、输出、退出码及工作目录；文件变更显示路径和红绿差异；思考和计划使用可展开的安全 Markdown 正文。
- 支持实时思考摘要、命令输出和计划更新。最终回答前仅在后端提供轮次耗时时显示 Worked for；缺失时只显示 Worked，不推测耗时。
- 消息的操作栏同时显示时间和复制图标：用户消息为「时间 → 复制」，回复为「复制 → 时间」。时间来自 Codex 的轮次时间（用户消息及中间消息使用开始时间，最终回答优先使用完成时间），按浏览器本地时区显示；悬停时间可查看完整日期及其含义，旧历史缺失时间时不显示。手机触屏上操作栏常显。
- 回答、工具结果和代码块支持复制，成功后显示勾，约两秒后恢复复制入口；失败显示错误提示，可再次点击重试。菜单在点击外部、移走焦点或按 Esc 时关闭；选择模型或思考强度后保持打开。
- 默认使用 **Full access**。选择 **Ask for approval** 时，后端返回的审批请求显示 **Allow once / Deny / Cancel**；**Approve for me** 使用 Codex 原生自动审查。
- 请求用户输入的工具会显示问题和选项；当问题允许其他答案时，可填写 Other answer，非空内容优先于所选选项提交。未填写时提交所选选项；不同会话和审批请求的未提交答案互不复用。尚不支持的交互会明确返回错误，不会自动批准。
- 审批和发送由服务端控制并发。多个页面不能重复批准同一个请求，也不能同时启动同一会话的两个轮次。

标签会显示运行中或待审批数量。首次迁移旧偏好时，会在已固定的 Terminal 后加入 Codex；之后手动隐藏 Codex 的选择会保留。未固定 Terminal 的用户可从导航菜单打开 Codex。

## 刷新、重连和数据归属

Codex 进程由 sessiond 中的服务端插件持有，切换面板、刷新浏览器或重启 Web 服务不会主动停止任务。页面通过插件的 `events` 双向通道接收变化通知，复用宿主鉴权和远程机器路由。服务端将约 30 ms 内的通知合并，浏览器再合并触发按需快照请求；由本插件执行的会话空闲时不定时查询。大消息继续使用有容量限制的快照请求，避免超出通道的单帧上限。

通道断开后约 1.5 秒重连，连接成功后补一次快照；快照请求失败后约 4 秒重试。重连只读取状态，不自动重发消息或审批。切换会话会取消旧订阅；正在运行的会话在面板卸载后仍保留更新，结束后释放订阅。

由本插件执行的会话实时推送。查看外部 CLI 写入的历史会话时，服务端约每 2 秒通知页面只读刷新已持久化内容，不接管其执行进程；在本插件中接管会话后改用实时推送，关闭订阅后停止定时刷新。需要手动重新加载时，可点击顶部栏的 **Reconnect** 图标。对话内容顶部不再显示 **Refresh conversation** 按钮。不支持通道的旧宿主会提示更新宿主或使用 **Reconnect**，不回退到浏览器定时轮询。

重新打开页面默认进入会话首页；草稿保存在浏览器本地，按机器、项目、工作区和会话隔离；禁用浏览器存储时，当前页面内仍保留草稿，刷新后无法恢复。浏览器站点存储中可能包含草稿正文。

app-server 退出、插件禁用或 sessiond 重启会中断进程内任务。点击 **Reconnect** 可重新初始化并恢复已持久化历史；不会恢复已经中断的工具执行。队列保存在 sessiond 的插件内存中，尚未提交给 Codex 的排队内容不会写入 Codex 历史。app-server 异常退出后，状态查询和重连会保留队列并保持暂停；查看已保存的会话历史，核对是否有已执行但未收到确认的输入，再点击 **Run next**。恢复会话失败时仍保留队列，移除排队消息无需恢复会话。插件禁用或 sessiond 重启仍会清空内存队列，应先处理排队内容。发送或 Steer 响应丢失时，先检查会话和队列，再决定是否重新发送。

应用按端口隔离状态目录，但 Codex 仍使用 sessiond 用户的默认配置目录或既有 `CODEX_HOME`。因此同一账户的 Terminal、其他端口和本插件可能共享 Codex 账户及历史。不要同时在多个客户端继续同一个会话；在面板中继续 CLI 会话前，应退出持有该会话的 CLI；仅等待当前轮次结束可能仍保留写入权。

## `already has an active writer`

该错误表示同一会话已有其他 Codex 实例持有写入权，例如 Terminal 中的 CLI 或另一端口的插件。旧版插件查看快照时也会尝试恢复会话，从而触发冲突。

补丁现将未接管会话的快照改为 `thread/read` 只读历史，轮询会重新读取已持久化内容；发送消息时才尝试恢复会话。外部会话显示 **Stored history**，不提供其实时审批或停止控制。如果发送时提示占用，请退出原客户端中的该会话后重试，或新建会话。

更新补丁后需重新执行 `sh scripts/install.sh` 并手动重启对应的 `pi-web-sessiond` 才能生效。重启前先完成或停止正在运行的任务。

## 从回答创建分支

已完成回答下方的复制按钮旁提供 **Branch in new chat**。点击后，新会话保留到该回答所在轮次（含该轮）的历史，并自动打开，可继续输入；后续轮次不带入分支。原会话及其未发送草稿保留，新会话以“原名称 · 分支”保存并出现在历史列表中，刷新后名称仍保留。同一工作区出现重名时，自动依次使用“原名称 · 分支 2”“原名称 · 分支 3”等名称。原会话没有名称时使用首条消息摘要；摘要也为空时使用“Untitled conversation · 分支”。若分支已创建但命名失败，会打开新会话并提示命名失败，避免把成功创建误报为失败。

生成回答或提交操作期间按钮不可用；过程中的 commentary 消息不提供分支入口。分支沿用当前模型选择、思考强度、Plan 模式和工作区权限设置。分支只复制对话上下文，使用同一工作目录，不创建 Git 分支，也不回滚文件。

需要 Codex app-server 支持 `thread/fork` 的 `lastTurnId` 参数（本机 Codex CLI 0.162.1 协议已核对）；对应行为见 [OpenAI 官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。接口失败会显示错误并保留当前会话。

## 资源限制与首版边界

- 每个工作区惰性创建一个 app-server，同一插件实例最多保留 16 个工作区实例；没有运行任务和待审批的实例闲置 15 分钟后回收。
- 每个实例最多缓存 30 个会话；超限时淘汰一个空闲会话，后续可从 Codex 历史恢复。
- 每个会话展示最近 512 个条目，每页 40 个；单条显示最多 16,384 字符，超长内容标明截断。快照按 UTF-8 JSON 总字节数限制在 7 MiB 内；超限时先将较大的条目精简为带提示的文本，保留全部分页条目，再按需移除最旧的输入历史，保留完整的最近输入。审批内容不静默截断；若仅审批等必要字段已超限，会明确报错。完整历史仍由 Codex 保存，可通过 CLI 查看。
- RPC 等待上限为 25 秒；超时会停止该 app-server 并明确报错，避免把未知状态当成成功。超大协议帧同样报错并停止进程。
- 工作区删除或归属改变后，插件的周期检查会在约一分钟内清理该工作区的进程。
- 暂不支持内嵌登录或 Codex 与 Terminal 独立左右分屏。

禁用或卸载插件前应先停止或等待其任务完成。插件通过现有插件管理机制启停；停用会释放进程和订阅，保留 Codex 持久化历史。回退时使用原 release，或移除 `0006-codex-panel.patch` 后重新构建安装，再重启对应服务。

## 公式与历史图片

回答中的 `\(…\)`、`\[…\]`、`$…$` 和 `$$…$$` 使用 KaTeX 生成 MathML，由浏览器排版。代码块和行内代码保持原文；未完成或不支持的公式显示为可读源码。

恢复历史消息时，兼容本地路径、`url` 和 `image_url` 图片字段。内嵌 PNG、JPEG、GIF、WebP 图片按 512 KiB 分块加载，不占聊天快照的 7 MiB 额度；每个工作区的图片传输缓存最多 32 MiB。图片加载失败时提供 Retry。工作区以外的本地路径仍只显示文件名。

包含合并后的 `0006-codex-panel.patch` 的版本需要重新构建安装，并在允许中断会话时切换服务后刷新页面。修改和构建验证不会自动重启服务。
