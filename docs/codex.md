# Codex Panel 实施计划与记录

## 1. 任务目标与范围

原始需求：在 Terminal 这个 Panel 右边增加一个新 Panel，用于支持 Codex。

实现约束：Codex Panel 以独立的 `pi-web.codex` 插件实现，通过现有插件 API 注册面板、导航动作和服务端能力。对话界面、会话状态、协议适配及 Codex 子进程管理均归插件所有；宿主仅承担通用插件加载、路由和布局职责。

参考项目：[lezi-fun/codex-webui](https://github.com/lezi-fun/codex-webui)。

本计划默认将“右边”理解为：在现有 Workspace 工具标签栏中，紧邻 Terminal 右侧增加 **Codex** 标签，点击显示独立 Codex 面板；沿用当前同一时间显示一个 Workspace 工具的布局。若实际需要 Codex 与 Terminal 同时左右分屏，需要另行扩展布局、拖动尺寸和窄屏折叠设计。

插件首版已实现，交付文件为 `patches/0006-codex-panel.patch`。使用方法和已知限制见 [Codex 插件使用说明](codex-usage.md)。下方保留原始阶段清单；未勾选项不代表已完成，最终检查记录见文末。

首版完成以下闭环：选择工作区 → 打开 Codex → 新建或恢复会话 → 发送消息 → 查看流式回答和工具执行 → 处理审批 → 停止或继续对话 → 刷新后恢复。

## 3. 技术方案

### 3.1 接入方式

新增 `pi-web.codex` 插件，前端使用现有 Lit 与插件 API，后端通过 Codex app-server 接入真实会话。

插件交付与宿主边界：

- 插件源码集中在 `pi-web-plugins/codex/`，浏览器入口注册 `workspace.codex`，服务端入口承载 Codex 能力，遵循固定上游基线的插件 API 与生命周期。
- 本仓库仍以新增补丁交付插件目录及必要的注册、构建和打包变更；插件是运行时组织方式，补丁是当前分支的交付方式。
- 面板通过 `workspacePanels` 贡献点渲染，宿主组件不直接导入 Codex 面板或处理 Codex 协议。默认入口及旧偏好迁移优先使用通用插件机制；确需扩展宿主时，先记录现有 API 的缺口，并将改动限制为通用能力。
- 插件启用、禁用和卸载遵循宿主机制；禁用后撤销入口与订阅，卸载时清理插件拥有的资源。存在运行任务或待审批请求时，必须明确提示终止影响，保留持久化会话历史。
- Codex CLI 作为可选运行依赖，首次使用时检查可用性；缺失或插件禁用时，Pi 聊天与 Terminal 仍正常工作。

参考项目使用 app-server 桥接，提供会话、流式工具、审批和 diff 等交互；本任务借鉴其功能流程和状态处理，适配 pi-web 自有界面与运行方式，不要求部署第二套 WebUI。参考：[codex-webui README](https://github.com/lezi-fun/codex-webui)。

官方协议提供初始化、线程、轮次、流式事件和服务端审批请求；具体字段以实施时固定的 Codex CLI 版本及其协议 schema 为准。参考：[Codex App Server 官方文档](https://developers.openai.com/codex/app-server)。

建议数据通路：

```text
CodexPanel / CodexBrowserRuntime
              │ 现有插件请求与事件通道
              ▼
pi-web-server 路由及机器代理
              │
              ▼
sessiond 所在机器的 Codex 服务端插件
              │ 子进程 stdio
              ▼
        codex app-server
```

- 优先复用插件 peer/channel 和机器路由，不增加浏览器直连的公共端口。
- 由工作区所在机器执行 Codex，工作目录来自服务端解析后的工作区信息。
- 会话进程由后端管理，前端面板卸载只解除订阅，不终止正在执行的任务。
- 首版建议按机器与工作区隔离 app-server 实例，首次使用时惰性启动；同一工作区多个标签页共享后端实例。
- 实施前验证插件所在进程及生命周期，保证浏览器刷新、切换面板或 Web 服务重连不会误杀任务。

### 3.2 前后端职责

| 模块 | 职责 |
| --- | --- |
| 插件入口 | 注册 Codex 面板、图标、导航动作、排序、默认可见入口 |
| CodexPanel | 会话选择、消息区、输入区、模型设置、工具卡片、审批、错误提示 |
| CodexBrowserRuntime | 按机器/工作区管理订阅、缓存、草稿和当前会话 |
| Codex 协议适配层 | 请求 ID、初始化、消息解析、超时、事件归一化及版本差异 |
| Codex 服务对象 | 子进程、会话操作、审批请求、订阅快照、退出清理 |
| 服务端插件 | 绑定可信工作区上下文，暴露请求与事件通道，接入健康状态 |

拟新增目录：`pi-web-plugins/codex/`。文件可按 `pi-web-plugin.ts`、`CodexPanel.ts`、`CodexBrowserRuntime.ts`、`codexProtocol.ts`、`server/server-plugin.ts`、`server/codexService.ts` 和对应测试拆分；最终名称在实施时按上游约定确定。

### 3.3 会话和数据归属

- 运行时隔离键至少包含机器 ID、工作区 ID、Codex thread ID。
- Codex 持久化会话是历史记录的权威来源，浏览器缓存只用于显示加速。
- 应用仅保存选中会话、草稿和必要的工作区映射，不复制 Codex 登录凭据。
- 新会话使用当前工作区的 cwd；恢复已有会话前核验归属，不能按客户端任意路径启动。
- 首版新建会话与 Pi 聊天独立，不自动搬运 Pi 历史。
- 对 CLI 已有历史的发现和恢复先做兼容验证；未经验证不承诺接管正在 Terminal 中运行的 Codex 轮次。
- 现有按端口隔离的状态目录用于应用映射及日志。Codex 自身配置目录的共享与隔离必须明确记录；不能将应用目录隔离误认为 Codex 账户和历史也已隔离。

## 5. 测试与验收矩阵

| 类别 | 必测场景 | 通过标准 |
| --- | --- | --- |
| 注册及布局 | 默认标签、旧偏好、导航菜单、窄屏、Swap、折叠 | 入口可达、位置正确、已有布局偏好不丢失 |

| 流式协议 | 分片、交错、重复、错误、超时、未知事件 | 消息正确归并，异常可恢复 |
| 工作区隔离 | 多机器、不同 cwd、快速切换、工作区删除 | 不串消息、不串审批、不误用路径 |
| 审批 | 允许、拒绝、取消、过期、双客户端回复 | 决策唯一且对应正确请求 |
| 生命周期 | 刷新、断网、面板卸载、进程退出、daemon 重启 | 无进程泄漏，恢复语义符合约定 |
| 插件边界 | 启用、禁用、重新启用、卸载、缺少 CLI | 入口与资源随插件生命周期管理，Pi 与 Terminal 独立可用 |
| 访问控制 | 未授权请求、越界路径、伪造会话 ID、非法帧 | 服务端拒绝，无敏感数据泄露 |
| 兼容回归 | 终端滚动、回放、复制、触摸、组合键、尺寸变化 | 原补丁功能保持正常 |
| 构建安装 | 干净基线应用、依赖安装、测试、打包、缺少 Codex | 成功可复现，失败不替换已有版本 |
| 性能 | 长会话、大输出、反复打开面板、多订阅者 | 有明确输出上限，资源释放且交互可用 |

## 12. 推送驱动的状态更新（2026-10-16）

新增服务端 `peer.openChannel(events)`，复用宿主通道鉴权、工作区绑定、机器转发及连接生命周期。通道先只读验证 thread 所属目录，再订阅变化；不调用 thread/resume 抢占外部会话。消息、工具、审批、完成和进程退出均触发合并通知。通道仅发送小型变更通知，大快照保留在现有请求通道，避免 64 KiB 单帧限制。

浏览器取消固定 700 ms 查询，使用变化通知、显式操作及分页触发快照。进行中的快照若收到新通知，会在返回后补取；连接断开后重试并重新同步；切换会话、工作区或卸载时清理旧订阅，生成号屏蔽迟到结果。外部 CLI 历史及不支持通道的旧宿主使用手动刷新，无后台定时轮询。

新增测试覆盖空闲零请求、通知合并、重连、旧会话事件隔离、只读历史、目录越界和订阅释放；相关 31 项测试通过。
