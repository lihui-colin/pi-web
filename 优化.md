# Upstream Compatibility / Minimal Patch Requirements

本功能长期需要跟随：

```text
upstream = jmfederico/pi-web
```

升级。

首要目标不是重构代码结构，而是：

> Keep the customization as a thin patch that can be rebased onto future upstream releases with minimal conflicts.

---

## 1. 不重构现有 Panel 架构

不要重命名或重新定义官方已有概念，例如：

```ts
navigationPanelCollapsed
workspacePanelCollapsed
PanelCollapseController
PanelResizeController
mainView
workspaceTool
```

即使 `workspacePanelCollapsed` 在 swapped 模式下实际表示“折叠物理右栏”，也不要为了命名更漂亮将其重构为：

```ts
rightPanelCollapsed
```

因为这会扩大 diff，并增加未来 upstream merge conflict。

原则：

```text
Reuse upstream state.
Override behavior only where necessary.
```

---

## 2. Swap 优先通过 CSS Grid Placement 实现

不要改变组件树。

不要：

```text
remove main
recreate main
move children manually
duplicate workspace-panel
create alternate terminal container
```

优先只给 Shell 增加一个 class：

```text
panels-swapped
```

原始：

```text
Navigation | Chat | Workspace Panel
```

Swap：

```text
Navigation | Workspace Panel | Chat
```

通过 CSS Grid placement 实现。

概念上：

```css
.shell.panels-swapped main {
    grid-column: 5;
}

.shell.panels-swapped > workspace-panel {
    grid-column: 3;
}
```

具体规则根据现有 CSS 实现调整。

---

## 3. 不修改 Terminal / Workspace Plugin

禁止修改：

```text
pi-web-plugins/terminal/*
TerminalFacade
TerminalPanel
TerminalBrowserRuntime
PTY
terminal protocol
```

也不要针对 Terminal 写：

```ts
if (workspaceTool === terminal) ...
```

Swap 对所有 Workspace Panel 通用：

```text
Terminal
Files
Git
Tasks
Relays
third-party plugins
```

---

## 4. 不修改 Chat 内部

禁止修改：

```text
ChatView.ts
PromptEditor internal behavior
chat history
session transcript
chat streaming
```

Chat 只是整个 `<main>` Surface 被换到右边。

---

## 5. 保留现有 Collapse Controller

不要重写：

```text
PanelCollapseController
```

特别不要因为 swapped layout 修改：

```ts
workspacePanelCollapsed
```

的 public/internal shape。

Normal 模式：

```text
workspacePanelCollapsed
→ hide Workspace Panel
```

Swapped 模式：

```text
workspacePanelCollapsed
→ hide Chat / main
```

建议通过：

```text
panels-swapped
+
workspace-panel-collapsed
```

的 CSS 组合实现。

例如逻辑：

```text
normal + collapsed
    → Workspace Panel hidden

swapped + collapsed
    → main/Chat hidden
    → Workspace Panel stays visible
```

这样不需要改 Controller。

---

## 6. 保留现有 Resize Controller

不要重构：

```text
PanelResizeController
workspace panel width state
resize persistence
AppPanelEdgeControl
```

现有 Grid 的右侧宽度变量继续代表：

```text
physical right column width
```

Normal：

```text
Right = Workspace Panel
```

Swapped：

```text
Right = Chat
```

尽量让现有：

```text
workspace panel width
```

变量直接控制 grid column 5。

不要建立新的：

```text
chatSideWidth
rightPanelWidth
swapResizeController
```

除非现有架构确实无法复用。

---

## 7. Layout Preference 单独新增文件

为了减少与 upstream 文件的冲突，新增一个独立文件：

```text
src/client/src/panelLayoutPreference.ts
```

建议：

```ts
export type PanelLayout =
  | "chat-main"
  | "workspace-main";
```

以及：

```ts
readPanelLayoutPreference()
writePanelLayoutPreference()
```

默认：

```text
chat-main
```

这样新增文件通常不会与 upstream 发生 merge conflict。

不要把 preference 大量塞进：

```text
appState.ts
config schema
server config
workspace config
```

这是纯浏览器 UI preference。

---

## 8. 不修改公开 Plugin API

非常重要。

不要修改：

```text
src/plugin-api.ts
test-fixtures/plugin-api-baseline/*
public plugin API version
```

这个 Layout Swap 是 PI WEB 本地 UI 定制，不值得扩大成新的 public plugin capability。

否则未来官方 Plugin API 变化时维护成本会明显增加。

---

## 9. Action 通过内部 unstable context 实现

当前内部已经存在：

```ts
piWebUnstable
```

以及：

```ts
PiWebUnstableRuntimeContext
```

优先在内部增加类似：

```ts
toggleChatWorkspaceLayout?: () => void;
```

由：

```text
PiWebApp
```

提供具体实现。

Core Action：

```text
Swap Chat / Workspace Panel
```

调用：

```ts
context.piWebUnstable?.toggleChatWorkspaceLayout?.()
```

这样可以避免修改公开 Plugin API。

不要把这个方法加入：

```text
src/plugin-api.ts
```

---

只在：

```text
src/client/src/plugins/core/actions.ts
```

增加一个 Action。

不要重构：

```text
createCoreActions()
Action Registry
Plugin Registry
Action Palette
```

## 11. PiWebApp 修改限制

`PiWebApp.ts` 尽量只增加：

```text
1. 读取 layout preference
2. 一个 toggle 方法
3. 给 shell 增加 panels-swapped class
4. 给 piWebUnstable context 暴露 toggle
```

不要借机重构：

```text
render()
navigation
workspace selection
session controller
plugin host
routing
mobile tabs
```

---

## 12. shared.ts 只追加覆盖规则

不要重新格式化或重写现有 Grid CSS。

只在现有 desktop media query 附近增加：

```text
panels-swapped
```

相关 override。

目标形式：

```text
existing upstream CSS
+
small custom override
```

而不是：

```text
replace upstream layout implementation
```

---

## 13. Mobile 保持官方行为

Swap 第一版只要求 Desktop split layout 生效。

对：

```text
<= 1180px
<= 760px
```

等 responsive 模式：

```text
keep upstream behavior
```

不要为了统一 Desktop/Mobile 逻辑重构响应式系统。

---

## 14. 建议修改文件范围

理想情况下只涉及：

```text
NEW:
src/client/src/panelLayoutPreference.ts

MODIFY:
src/client/src/components/PiWebApp.ts
src/client/src/components/shared.ts
src/client/src/plugins/core/actions.ts
src/client/src/plugins/types.ts

TEST:
对应少量 test files
```

避免修改其他 production files。

如果实现过程中修改 production source 超过约 5～6 个文件：

```text
STOP and review the design.
```

检查是否发生了不必要的重构。

---

## 15. 不为了“命名正确”扩大 Diff

这是长期维护 fork。

因此：

```text
small awkward compatibility layer
```

通常优于：

```text
large clean refactor
```

例如官方已有：

```ts
workspacePanelCollapsed
```

即使 Swap 后这个名字不再 100% 准确，也优先保留。

原因：

```text
upstream changes
      ↓
git rebase upstream/main
      ↓
越少修改官方核心结构
      ↓
越少 conflict
```

---

## 16. Git 历史要求

整个功能最终 squash 成：

```text
feat: allow swapping chat and workspace panels
```

长期保持：

```text
upstream/main
      │
      │ official commits
      │
      └── one custom commit
            feat: allow swapping chat and workspace panels
```

升级流程：

```bash
git fetch upstream
git checkout terminal-mode
git rebase upstream/main
```

然后：

```bash
npm test
npm run build
```

使用仓库实际定义的测试命令。

---

## 17. 启用 Git rerere

建议维护分支开启：

```bash
git config rerere.enabled true
```

如果未来官方反复修改：

```text
PiWebApp.ts
shared.ts
```

第一次解决 rebase conflict 后，Git 可以复用类似冲突的解决方案。

---

## 18. Patch Review 标准

实现结束运行：

```bash
git diff upstream/main...HEAD
```

人工检查。

理想 diff 应该非常容易阅读：

```text
+ panel layout preference
+ one Action
+ one toggle callback
+ one shell class
+ several CSS overrides
+ tests
```

如果 diff 出现：

```text
large component moves
large file formatting
renaming existing classes
controller refactor
plugin API changes
Terminal modifications
ChatView modifications
```

应回退并重新实现。

---

# 最终维护目标

理想状态不是：

```text
our custom version of PI WEB
```

而是：

```text
official PI WEB
+
one small layout patch
```

每次官方发布新版：

```text
Official vNext
      +
Swap Layout Patch
      ↓
our vNext
```

核心原则：

> Prefer additive overrides over structural refactors.

> Do not rename or redesign upstream abstractions merely to make the custom feature cleaner.

> Keep the patch isolated, shallow, and easy to rebase.
